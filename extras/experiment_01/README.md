# 実験1：Shorts に「関連動画」リンクを付ける（計測のしかた）

- 設計：`設計_2026-10-20.md`（期間 2026-10-21〜11-17、前後比較）／リンクを付けた記録：`リンク記録.csv`
- 計測ビュー：`sql/05_experiment_tracking.sql` の `mart.v_experiment_tracking`（日ごとの区分と指標）と `mart.v_experiment_summary`（区分ごとの1日あたりの平均）

## 毎週の更新（3行）
1. YouTube Studio から前回と同じ形の CSV（日別の指標・トラフィックソース日別・動画一覧など）を書き出し、`data/raw` に置き換える
2. `run_load_stg.bat` → `run_mart_reload.bat` を流す（全件入れ替えなので、何度流しても同じ結果になる）
3. SSMS で `SELECT * FROM mart.v_experiment_summary;` を見る。「前」と「期間中」の `related_shorts_per_day`（主の指標）を並べ、1日3回以上かを確かめる

## 見る指標
| 列 | 中身 |
|---|---|
| related_shorts_views | 主の指標。流入元「関連のショート動画」（Shorts のリンクから長尺へ）の視聴回数 |
| longform_approx_views | 副の指標。全体 −「ショート フィード」−「関連のショート動画」で長尺の視聴を近似（e_05 と同じ） |
| watch_hours | チャンネル全体の総再生時間（長尺だけの日別の再生時間は CSV にないため） |
| shorts_posted／longform_posted | その日に公開した本数（比べるときにそろえる） |

## 手元の CSV（〜10/14）での確認（2026-10-20、同じロジックを DuckDB で流した）
| 区分 | 日数 | 関連のショート動画（1日あたり・合計） | 長尺の近似（1日あたり） | 全体（1日あたり） | 公開本数（Shorts／長尺） |
|---|---|---|---|---|---|
| それ以前（7/14〜9/22） | 71 | 0.15・11回 | 71.92 | 354.93 | 126／111 |
| 前（9/23〜10/14） | 22 | 0.14・3回 | 51.91 | 517.14 | 68／26 |

- 「前」は 10/15〜10/20 の CSV がまだないので22日分。「期間中」「後」の行は、10/21 以降の CSV を入れるまで出てこない
- 基準：主の指標は今 1日 0.14回。期間中に 1日3回以上になれば「誘導の入口として使える」と判断する（設計で先に決めた基準）
