# youtube-data-mart 5分説明（下書き・面接用）

## 1. 何を作ったか（30秒）
- 自分の YouTube チャンネルのデータ（CSV 7種・動画342本・93日分）を、pandas → SQL Server（stg → mart）→ Power BI → 重回帰とつないだ
- 1本目は CSV を Power BI で直接読んでいたので、2本目は「取り込み・保管・分析用の形・可視化・分析」を分けた

## 2. なぜこの設計か（2分）
- **粒度を先に決めた**：日・動画×日・流入元×日・登録元×日・動画（期間合計）の5つのファクト。粒度の違う数字を混ぜない
- **代理キー**：動画ID（文字列）は業務キーとして UNIQUE、ファクトは整数キーで結ぶ。日付ディメンションは再帰 CTE で切れ目なく作り、視聴0回の日も行を持つ → 7日移動平均が「7日」の平均になる
- **何度流しても同じ結果**：読み込みの最初に全件消して IDENTITY も振り直す（2回流して確認）
- **確認クエリ3つ**：行数・合計・ディメンションに結びつかない行（0件）。1本目で「103回の差」を手で見つけた経験から、毎回機械的に確かめる形にした
- 答え合わせ：10/14 の7日移動平均 602.29、合計 36,577回が1本目（SQL・Power BI）と一致

## 3. 何が分かったか（1分30秒）
- 目的変数は「1日あたりの視聴回数」（累計だと古い動画ほど多いだけになるため）
- Shorts は長尺の約2.8倍／日（95%CI 2.4〜3.3）。公開直後が一番伸びて1日1.6%ずつ落ちる。長尺はクリック率だけが効く（+1pt で ×1.07）。土日・祝日の公開は関係なし
- 統計の確認：VIF（Shorts と長さは相関 -0.99 なので同時に入れない）、HC3（Shorts と長尺で残差のばらつきが3倍違う）、5-fold CV（R² 0.42 ± 0.09）
- 相関であって因果ではない、と分けて説明する
