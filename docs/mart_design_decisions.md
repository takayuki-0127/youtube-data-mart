# mart 設計で決めたこと（面接の5分説明用）

1. **ファクトの粒度を先に決めた**：日（チャンネル全体）・動画×日・流入元×日・登録元×日・動画（期間合計）の5つ。粒度が違う数字を1つの表に混ぜない
2. **代理キー（INT IDENTITY）を主キーにした**：YouTube の動画ID（11文字の文字列）は業務キーとして UNIQUE で持ち、ファクトは整数キーで結ぶ。JOIN が軽く、ID の表記ゆれ（前後の空白）にも強い。日付だけは 20260714 形式のキー
3. **日付ディメンションは再帰 CTE で切れ目なく作った**：視聴0回の日にも行があるので、7日移動平均が「7行」ではなく「7日」の平均になる（10/14 = 602.29 で確認）
4. **何度流しても同じ結果になるようにした**：読み込みの最初にファクト → ディメンションの順で全件消し、IDENTITY も振り直してから入れる（2回流して同じ結果を確認）
5. **確認クエリ3つを必ず流す**：①ファクトの行数＝stg の行数 ②視聴回数などの合計＝stg の合計 ③ディメンションに結びつかない行が0件。1本目で見つけた「103回の差」のような食い違いを、取り込みのたびに機械的に見つけるため
6. **種類（Shorts／長尺／Live）はディメンションに切り出した**：判定ルール（60秒以下・長さ0 か LIVE）を1か所にまとめ、Power BI の RLS（Shorts担当／長尺担当）もこの表で絞る
